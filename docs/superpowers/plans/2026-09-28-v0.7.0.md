## P0 — Close the deep audit

### Task 1: Persist and replay tool context across turns
**Problem:** `ContextManager` and the session JSONL only ever store user/assistant
*text*. `toCoreMessages()` drops tool calls/results, so between turns and after
`--resume` the model loses every tool it ran (files read, commands executed) —
causing redundant work and hallucinated state. `truncateOldToolResults` is dead code.

**Files:** `src/agent/Agent.ts`, `src/context/ContextManager.ts`, `src/session/Session.ts`,
`src/types.ts`, `src/ui/App.tsx`, tests.

**Design:**
- Thread the AI SDK's `toolCallId` through the tool pipeline: `CoreTool.execute(args, { toolCallId })`
  → `executeTool(name, args, toolCallId)` → `tool-call-start`/`tool-call-result` events carry `toolCallId`.
- Add `toolCallId` to the event payloads and to `ChatMessage.tool_call`.
- `ContextManager` gains typed entries for tool interaction: store the assistant
  `tool-call` and the matching `tool-result` (with `toolCallId`, `toolName`, args/result),
  and reconstruct them in `toCoreMessages()` as AI SDK `CoreAssistantMessage` (content
  parts with `type: 'tool-call'`) followed by a `role: 'tool'` message.
- Session JSONL: persist these as new message `type`s (`tool_use` / `tool_result`) with
  `toolCallId`; `Session.load()` must accept old files (no toolCallId) unchanged.
- Ensure the first reconstructed message is a `user` turn (Anthropic requirement).

- [ ] **Step 1:** Extend `ToolResult`/event types and `ChatMessage` with `toolCallId`.
- [ ] **Step 2:** Add failing tests: a context with user → assistant tool-call → tool-result
      → assistant text reconstructs to a valid `CoreMessage[]` starting with `user` and
      containing a `tool` message.
- [ ] **Step 3:** Implement `ContextManager` storage + `toCoreMessages()` reconstruction.
- [ ] **Step 4:** Wire `Agent` to emit `toolCallId`; persist tool turns in `App`/`Session`.
- [ ] **Step 5:** Verify resume and `--resume` replay tool context; full suite green.

### Task 2: Associate tool results by `toolCallId`, not name
**Problem:** `App.tsx` matches a `tool-call-result` to the most recent in-progress
`tool_call` **of the same name**. Parallel calls to the same tool can cross-wire.
- [ ] Match on `toolCallId`; fall back to name only when the id is absent.

### Task 3: Hook events — emit or de-advertise
**Problem:** `preCompact` and `notification` are listed as discoverable events but are
never emitted.
- [ ] Emit `preCompact` before compaction (pass a minimal context) and `notification`
      on notable system notices; otherwise remove them from `HOOK_EVENTS` + the `/hooks` help text.

### Task 4: Semver pre-release precedence
**Problem:** `isNewerVersion` strips `-rc.1`, so `1.0.0` vs `1.0.0-rc.1` compares equal.
- [ ] Implement pre-release precedence per semver (a prerelease is lower than its release).
